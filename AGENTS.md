# Project instructions for coding agents

## Project

SPUR Project Placeholder is the starting repository for the SPUR project. Its purpose,
audience, and technology choices have not been defined yet; do not guess them.

When project documents are added, respect the approved decisions and their agreed order
of precedence. If a request conflicts with an approved decision, explain the conflict and
ask before proceeding.

## Working rules

- Explain technical terms in plain language.
- Show each command before running it and explain in one plain sentence what it does.
- After running commands or changing files, say what happened and how you verified it.
- Ask rather than guess when requirements are ambiguous; clearly label assumptions.
- Do not invent facts, APIs, package names, or citations.
- Keep changes focused on the request and follow existing project conventions.
- Never commit secrets, API keys, tokens, or personal data.
- Ask before adding a dependency, service, or anything that may cost money.
